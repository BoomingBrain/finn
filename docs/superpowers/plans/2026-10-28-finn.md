# FINN — Financial Investment Agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a mobile-first web app where an investor gets a ranked, de-noised digest and threshold alerts for an 18-stock NSE portfolio (Push), and can open a cited research dossier on any NSE ticker, built only from primary sources (Pull).

**Architecture:** Ingestion runs offline, on the developer's machine or GitHub Actions. It pulls announcements, prices, PDFs and screener.in data, runs rules and then cheap LLM extraction, and commits JSON snapshots to the repo. Dossiers for the demo tickers are precomputed. A single Docker service (FastAPI) serves the API and the built React PWA from those snapshots. At request time it calls external sources and LLMs only for live research on a ticker that has no precomputed dossier, and that path sits behind a spend cap and a per-IP rate limit. Numbers and verdicts are always computed in code. The LLM extracts, explains and argues, but never judges a number.

**Tech Stack:** Python 3.12, uv, FastAPI, httpx, yfinance, pandas, selectolax, PyMuPDF, anthropic SDK, pydantic v2, pytest · Vite, React 18, TypeScript, Tailwind CSS v4, Vitest · Docker on Hugging Face Spaces (fallback: Render) · GitHub Actions (ingestion + deploy sync).

**Spec:** `1. ENAM_AI_Engineer_Build_Challenge_Main.pdf` and `2. ENAM_AI_Engineer_Build_Challenge_Reference.pdf` (repo root, git-ignored). No separate design doc exists; the Decisions section stands in for one. Data-source facts come from `docs/spikes.md` (Task 0), which **overrides** any endpoint or field name in this plan.

## Decisions (made in lieu of a design doc — review these first)

- **Product point of view:** "FINN only speaks when it matters." Each related group of filings becomes one **event**, ranked into a tier. **Critical** events get a rich card (results numbers or appointee profile), **notable** ones a one-line summary, and **routine** ones are collapsed behind a count. Every event shows that day's price move. Every Pull claim carries a citation chip that opens the source PDF at the right page.
- **Tiering (the judgment call):** critical = results, M&A, management_change, fund_raise, litigation, pledging · notable = credit_rating, capex, insider_trading, dividend, bonus_split, press_release · routine = earnings_call, investor_meetings, postal_ballot, agm_egm, unclassified.
- **Interaction model:** three tabs (Brief, Watch, Ask) connected so the investor moves from "what changed" to "why it matters":
  - **Built:** "Ask about this" on every Brief card opens the dossier with the event pinned as context. Threshold sliders show "would have fired N times in the last 30 days" from stored prices, so "unusual" is set against evidence.
  - **Next steps (not built):** swipe-to-dismiss triage, and natural-language questions answered only from the cited dossier ("did X hit its margin target?").
- **Data & hosting architecture:** NSE, BSE and screener.in may block cloud IPs, and free hosts sleep and lose their disk. So ingestion is offline (local or Actions) and commits snapshots, and the deployed app is a read-only server over committed JSON.
  - **Client-side state:** user state (thresholds, seen alerts) lives on the device in localStorage. The server computes alerts from thresholds sent as query params. No database.
  - **Hosting:** one Docker service on **Hugging Face Spaces**, because it sleeps only after 48 h idle (Render: 15 min). The daily ingest commit redeploys it, which also keeps it awake. Render runs the same Dockerfile as a fallback.
  - **Platforms:** two in total. GitHub runs the repo, the ingest cron and the deploy sync; the Space hosts the app.
- **Primary sources:** Pull numbers come from screener.in tables, which are standardised from the companies' own exchange filings (primary data, reformatted). Guidance and narrative come only from concall transcripts and annual reports. No news, broker notes, or model knowledge.
- **Results numbers:**
  - **Corporates:** EBITDA = PBT + finance costs + depreciation − other income, in ₹ Cr.
  - **Banks and NBFCs:** shown as NII (net interest income), PPOP (pre-provision operating profit, if reported), PBT and PAT, with EBITDA marked "n/a for lenders".
  - **Column selection:** Q2/Q4 filings carry half-year and full-year columns, so quarter columns are picked in code from each column's period length and end date.
  - **Cross-check:** extracted Revenue/PAT are checked against screener's quarterly table, and a card that disagrees is marked "unverified".
- **Promised vs Delivered:** the model only *extracts* targets as structured data (metric, comparison, value, period, quote, source). Code computes the actual from reported quarters and the verdict (met / partly / missed / pending / not checkable). The model then writes a one-line explanation and cannot change the verdict.
- **Management changes:** the bio is extracted from the filing itself (SEBI Reg 30 appointment disclosures include a "brief profile"). If the filing has no profile, the card says "No profile in filing" and links the filing. **LinkedIn scraping was deliberately avoided:** it breaks LinkedIn's terms, needs a login, is blocked from servers, and matching the right person by name alone is unreliable.
- **Models:** bulk tier `claude-haiku-5-5` (classification fallback, extraction, summaries, explanations); reason tier `claude-sonnet-5-5` (Bull vs Bear only). Because ingestion is precomputed, viewers trigger no LLM calls except live research on new tickers.
- **Push freshness:** "the moment" means the next ingest run: every 2 h on market days, plus an evening run after EOD prices. Real-time exchange streaming and browser web-push are next steps.
- **Portfolio (18):** RELIANCE, HDFCBANK, INFY, BHARTIARTL, ITC, LT, SUNPHARMA, TITAN, BAJFINANCE, ASIANPAINT, DMART, POLYCAB, DIXON, PERSISTENT, TRENT, IRCTC, DEEPAKNTR, KPITTECH (sector field marks HDFCBANK = Banks, BAJFINANCE = NBFC). **Research demo (4):** PIDILITIND, HAL, CDSL, NAUKRI.

## Global Constraints

- Mobile-first: designed at 390 px wide, fully usable at 360 px, no horizontal page scroll.
- Portfolio is 15–20 NSE/BSE-listed companies; research demo set is 3–5 companies.
- Research must generalise: it works on any NSE ticker that screener.in covers, with no per-company code.
- Pull is grounded only in primary sources (see Decisions). No news, no broker notes, and the model's outside knowledge is not allowed. Push-side enrichment is exempt.
- Digest window defaults to the last 24 hours and is user-selectable (24h / 3d / 7d / 30d).
- Alert thresholds are user-configurable. Defaults: volume > 2.0× its 20-trading-day average, price move beyond ±5.0% in a day. Ranges: price 0.5–50 %, volume multiple 1.1–10.
- Results cards show Revenue, EBITDA, PBT and PAT (lenders: NII, PPOP, PBT, PAT) for this quarter vs. last quarter (QoQ) and vs. the same quarter a year ago (YoY).
- The deployed app never fetches portfolio data from NSE/BSE/screener/Yahoo at request time. It serves `data/snapshot/`. The only request-time external calls are live research for tickers without a precomputed dossier.
- Cost: rules before any LLM call; bulk tier for extraction; reason tier only for Bull vs Bear. All LLM responses and documents are cached. The live-research cap is `DAILY_LLM_BUDGET_USD` (default 2.00) and `LIVE_RESEARCH_PER_IP_PER_HOUR` (default 3). Serving a precomputed dossier is never limited.
- Free tiers only. Yahoo tickers use `.NS`; internally symbols are uppercase with no suffix.
- `docs/spikes.md` overrides any endpoint, field name or source choice written in this plan.

## Review Focus

1. **A source blocks the server or the CI runner, or fails mid-ingest.** Expected: the app serves the last committed snapshot with an "as of" stamp, and stale data is flagged. Ingest records failed sources and keeps the others. Live research on an unseen ticker shows "Couldn't fetch sources for {SYMBOL} from the server." instead of crashing. Checks: Task 0 Actions spike, Task 5 stale smoke, Task 12 forced-failure smoke.
2. **Lender results (HDFCBANK, BAJFINANCE).** Expected: NII/PPOP/PBT/PAT with EBITDA "n/a", never a nonsense EBITDA. Tests: Task 4 `test_bank_layout_nii`, `test_nbfc_layout_uses_finance_costs`, `test_lender_without_ppop_omits_it`, `test_sector_override_forces_lender`.
3. **Q2/Q4 filings with half-year and full-year columns, figures in lakhs, or unreadable PDFs.** Expected: the right three quarter columns, values in ₹ Cr, or an "unreadable — open filing" card. Never wrong numbers. Tests: Task 4 `test_q2_filing_picks_quarter_columns`, `test_q4_filing_picks_quarter_columns`, `test_period_inferred_from_header`, `test_lakhs_normalised`, unreadable tests. Task 14 cross-check and eval.
4. **Guidance that can't be checked** (capex, order book, NIM, a period not yet over, a vague "double-digit growth"). Expected: "pending" (with tracking value) or "not checkable", never an invented verdict. Tests: Task 10 verdict matrix.
5. **A results day with 4 related filings for one company, or a window with nothing in it.** Expected: one event card linking all four documents, and a calm "Nothing material in the last 24 hours." state. Tests: Task 6 clustering tests; Task 5 quiet-state smoke.

## Testing Policy

TDD is kept only for logic that can be **silently wrong**, where the output looks plausible while the number or verdict is wrong:
- `compute_results`, `select_quarter_columns`, lender layout (Task 4)
- `classify_rule` (Task 3)
- `cluster_events` (Task 6)
- `detect_signals`, `backtest`, `alerts_for` (Task 7)
- metrics (Task 9)
- guidance period/actual/verdict logic (Task 10)
- `drop_uncited` (Task 11)
- `SpendBudget` and `RateLimiter`, because they guard money (Tasks 1, 12)
- `crosscheck` (Task 14)
- Two UI tests: `ResultsCard` formatting (Task 5) and the backtest text (Task 7)

**Dropped, replaced by smoke checks:**
- Snapshot store and LLM-router routing/caching tests: failures are loud, and LLM usage shows up in the logs.
- NSE/BSE/screener parser tests: these are run against captured fixtures in smoke steps, and the metric tests consume the parsed fixtures.
- Digest windowing and API validation tests: visible immediately in the UI.
- Research orchestration/SSE tests: checked with curl.
- Most UI tests: layout bugs are caught on a real phone at each nightly checkpoint.

The reason is the 4-day deadline. Every hour goes where a bug would be invisible.
